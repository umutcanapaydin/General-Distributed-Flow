GDF — General Distributed Flow v1.0 Schemadelegated lane · agents merge, gatedPROVISIONAL

PM agent orchestrates via Jira · builders code & merge behind mechanical gates · risk-tiered technical bench per PR · the owner reviews commits + Jira asynchronously, protected by backpressure, tripwires and an auto-revert window. Sibling of General Pipeline — one constitution, two flows.

1 · Two Lanes, One Constitution

GP — GENERAL FLOW (v3.3)

  • Owner IN the loop: reviews every milestone, runs his own tests, makes every commit
  • Clear PRD · hash-frozen milestone plans · waves + milestone closure
  • For production-critical work and ⛔ surfaces

GDF — DISTRIBUTED FLOW (v1.0)

  • Owner ASYNC: daily digest, weekly telemetry, auto-revert window
  • Fuzzy PRD welcome · per-TASK acceptance criteria, hash-frozen at Jira level
  • For fast, internal, non-production-critical projects — eligibility charter enforced
Shared constitution (referenced from GP v3.3, pinned — never copied): evidence rule (agent-asserted content never gates) · default-deny permissions · security baseline · escalate-NOW class · files-not-sessions continuity · EXPERIENCE→register→council loop. GDF's deviations live in a one-page override appendix — GDF-001 records, in plain text, that the owner consciously overrode GP's A1 bright line for this lane only.

2 · The Flow (five stages)

GATE 0
Intake — gdf-config.yaml + Charter + gdf-check ★ GDF-006
executable, not documentary
PM walks the owner through the config as questions: tracker (Jira site/key/statuses) · git host/repo/trunk · quality gate (SonarCloud or CI-native + thresholds) · artifact store (JFrog/GHCR/none) · deploy target (or none) · scans · per-repo ⛔ globs · tunable limits. Secret names only — never values.
⛔ scripts/gdf-check.sh must PASS (no placeholders · no leaked secret values · charter signed · branch protection confirmed · SonarCloud auto-analysis OFF) — no tasks, no branches, no PRs until green.
↓
STAGE 1
Discovery / Shaping
PM + owner · fuzzy intent → frozen tasks
PM converts intent into Jira tasks with Given/When/Then acceptance criteria; owner batch-approves async (timeboxed). AC hash-frozen at creation — criteria evolve by successor tasks (lineage-linked), never by editing in-flight; a task superseded >2× → owner review.
Injection defense: agents act only on tasks with the owner-provenance gdf-approved label; comments (any author, incl. other agents) are DATA, never commands.
↓
STAGE 2
Build — parallel builder agents
atomic claim · single-writer PRs
Atomic claim (Jira transition + assignee in one call; re-read before work) → feature branch → code + unit tests + the citing test proving the AC through the live entrypoint → Semgrep pre-scan → PR with AC-hash + Jira key + trailers (GDF-Agent · GDF-Task · GDF-Run). Stale-task sweep reclaims silent tasks (45 min); throwback counter escalates at N=3 → Blocked-Human.
↓
STAGE 3
Gate — CI + Quality Gate + Tiered Bench
fresh-eyes · required status checks

LOW · ≤150 LOC

  • no ⛔-glob, no deps/schema/CI
  • ONE combined reviewer
  • full checklist + secret scan + test-integrity

MED · ≤600 LOC

  • app logic, ≤3 modules
  • Code Reviewer + Tester
  • affected-flow E2E subset

HIGH · ⛔-glob / >600 / deps / schema

  • FULL BENCH: CR · Tester · SW Eng · Quality · DevOps · Data (on data globs)
  • fault-injection mandatory
  • + OWNER required review on ⛔ paths (sync!)
Tier computed by a labeler bot from globs + diffstat — never agent-asserted; one-way ratchet up. Anti-gaming: cumulative LOC per Jira task counts (splitting doesn't dodge the bench). Verdicts = GitHub PR reviews (PASS/MINOR/BLOCKING + file:line + evidence) mapped to required checks.
↓
STAGE 4
Merge — agent-executed, mechanically gated ★ the override
squash · linear · tested-SHA
Authoring builder merges when ALL required checks are green. Branch protection: no force-push · no deletion · enforce_admins ON · squash-only (1 commit = 1 PR = 1 task = 1 agent) · CODEOWNERS = owner on control plane + ⛔ globs · merged SHA = the SHA CI tested. Done in Jira is reachable ONLY via the transition recording the merge SHA — git is truth.
Backpressure: 5 unreviewed merges (or 1 unreviewed HIGH) → merges pause · owner silent 3 days → pause · PRs queue in Awaiting-Owner; work continues on branches.
↓
STAGE 5
Deploy / Verify — CI only
agents trigger · CI holds ALL credentials
Trunk merge → auto-deploy to staging via CI. Production: tag + GitHub environment protection with the owner as required reviewer (the async lane's moment with teeth) → CI deploy → health check → CI-executed rollback on failure. Agents never hold SSH keys, registry passwords, or broad PATs — a CI check greps agent workspaces for secret patterns.

4 · Jira Lifecycle & Throwback

To Do ──► In Progress ──► In Review ──► Done (Done ⇐ ONLY via merge-SHA transition)
            + Blocked-Human (throwback N=3 / halt) · Awaiting-Owner (backpressure queue)

Throwbacks: bench BLOCKING → Build · CI/QG fail → Build · CI-config fail → DevOps seat self-fix ·
test-env issue → Tester seat · AC gap → Discovery (successor task) · 3rd failure → Blocked-Human + escalate-NOW

5 · Tripwires — auto-freeze of ALL agent merge rights

#EventEffect
1Verified secret in a merged commitBranch protection flips to human-review-on-everything via a toggle agents cannot operate. Only the owner unfreezes, with a written cause+fix note. PRs keep queueing — work never stops, merging does.
2⛔-glob change reaching a protected branch without owner approval
3High/critical security finding in a deployed artifact
4≥2 reverts in 24h, or trunk CI red >1h
5Anomalous agent behavior (push outside PR path · missing trailers · control-plane attempt)
Eligibility / graduation tripwire: external users, production-revenue dependency, or a ⛔-critical core appearing in a GDF project → merges freeze → the project graduates to GP governance. Fast lane ≠ back door. · Provisional expiry: 3 projects or 60 days → mandatory retro before re-charter.

6 · Telemetry (owner's weekly read — computed by a job agents cannot write to)

per authoring agent, rolling 4 weeks:  merges · post-merge fix rate (path overlap, N days) · revert rate ·
churn (<14-day rewrites) · cycle time (claim→merge) · QG first-pass rate  + data-health line (migrations · rollback-script CI pass)
